# inverseCellReduce: centraliser lookup, math-layer review

This was a Lead request (2026-10-18; the owner approved a behaviour-preserving rewrite). The review is read-only: code reading of the worktree `tcgraph-perf`, branch `perf/inverse-cell-centraliser` (21595bd plus uncommitted changes). Nothing was built or run.

**Notation.**
- f_k: the reduced expansion of factor k.
- Q_u = f_0 ⋯ f_{u-1}, freely reduced. These are the trie nodes.
- Prefix test for a pair i < j: A_s⁻¹ f_i⁻¹ A_s = f_j, with A_s = f_{i+1} ⋯ f_s = Q_{i+1}⁻¹ Q_{s+1}.
- Suffix test: B_s f_j⁻¹ B_s⁻¹ = f_i, with B_s = f_{s+1} ⋯ f_{j-1} = Q_{s+1}⁻¹ Q_j.
- In both, s runs over i ≤ s < j, i.e. u = s+1 runs over [i+1, j].

## (1) Completeness: CONFIRMED (proof)

1. **Solution set.**
   - Write x = f_i⁻¹ = p·c_x·p⁻¹ and y = f_j = q·c_y·q⁻¹, with p = the conjugator and c = the core (`conjugatorLength`; the cores are cyclically reduced because the expansions are freely reduced, as `expandFactor` always free-reduces since PR #6).
   - The classes match, so c_y is a rotation of c_x: c_x = z·w and c_y = w·z, with z = c_x[:r].
   - Then a₀ = p z q⁻¹ solves a⁻¹ x a = y. The full solution set is C(x)·a₀.
   - C(x) = ⟨p ρ p⁻¹⟩, where ρ is the primitive root of c_x. In a free group the centraliser of a nontrivial element is cyclic and generated by its root, and the root of p c_x p⁻¹ is p ρ p⁻¹ because c_x is cyclically reduced.
   - So the solutions are exactly a_m = p ρ^m z q⁻¹, for m ∈ ℤ. This matches `solve_`.
   - `minimalPeriod` only accepts periods that divide the length, so ρ is the primitive root.
   - r comes from the two least-rotation indices, and the result is checked (`rotated == y.core`; a mismatch falls back to the loops). Any other valid r differs by a multiple of |ρ|, and that difference is absorbed in m (c_x[:r+|ρ|] = ρ·c_x[:r]).
2. **The scan becomes a lookup.**
   - Prefix test at s ⇔ A_s ∈ {a_m} ⇔ Q_{s+1} = Q_{i+1}·a_m for some m.
   - So the smallest passing s is the smallest u ∈ [i+1, j] such that Q_u is a node equal to base·a_m (base = Q_{i+1}), minus 1.
   - `consider_` takes, per candidate node, the smallest u in [lo, hi] = [i+1, j] (the per-node u lists are ascending by construction). `best_` takes the minimum over all candidates. This is the old first s.
3. **The suffix form.**
   - With g = B_s⁻¹ = Q_j⁻¹ Q_{s+1}, the test is g⁻¹ f_j⁻¹ g = f_i.
   - So base = Q_j, x = f_j⁻¹ (`neg_form_(j)`), y = f_i (`pos_form_(i)`), u = s+1 ∈ [i+1, j], and smallest u ⇔ smallest s. The orientation is correct.
4. **Walking a candidate is exact.**
   - Reading the reduced word t = base⁻¹F letter by letter from base follows the tree path from base to F. That path goes up to the common ancestor and then down to F, so each of its nodes is a prefix of base or of F.
   - The trie is prefix-closed (`step` only appends a child or returns the parent).
   - So: F is a node ⇔ the walk never leaves the trie. `walk_` / `find` never create nodes.
5. **The m range and the closed form.**
   - m = 0 is explicit.
   - For each of ρ and ρ⁻¹ (which give m > 0 and m < 0), let t_c and u_c be the cancellation of p's tail with ρ^∞ and of S = reduce(z q⁻¹)'s head with the end of ρ^m. Both are maximal.
   - If m|ρ| > t_c + u_c, the two cancellations cannot meet: ρ^m is reduced (ρ is cyclically reduced) and at least one middle letter survives. So reduce(p ρ^m S) = p[:|p|−t_c] · ρ^∞[t_c : m|ρ|−u_c] · S[u_c:], as coded.
   - The m with m|ρ| ≤ t_c + u_c, i.e. m ≤ ⌊(t_c+u_c)/|ρ|⌋ = `m_explicit`, are built explicitly with stack reduction.
   - Every m > m_explicit corresponds to consumed = m|ρ| − u_c ≥ t_c + 1, the index condition in the walk.
   - The walk along ρ^∞ visits the common prefix of all larger candidates. By point 4, if it falls off the trie at some point, then every candidate with a larger m is absent too, so stopping there loses nothing.
   - It terminates because the words p'·ρ^∞[t_c:c] are reduced and pairwise distinct, while the trie is finite.
   - (Aside: t_c = 0 always, because p c_x p⁻¹ and its inverse are reduced; the general code is harmless.)
6. **Ties and order.**
   - The pairs are visited in the same (i, j) order with the same key test.
   - Within a pair, the prefix form is fully resolved (minimal s) before the suffix form is tried.
   - Each hit is re-verified with the old exact test. On a mismatch, or on an "unsupported" case (cores of different length, rotation not found, a trivial factor, a letter outside {a, A, b, B}), the code falls back to `directPair` / `directScan`. The fallbacks can only restore the old result.

## (2) Trie: CONFIRMED

- **Hash-consing:** a node is (parent, last letter). `step` cancels against the parent when the letter inverts the node's last letter; the root is excluded by `v != kRoot`, so the root's dummy code is harmless. So every freely reduced word has exactly one node, and equality is node identity.
- **`step`:** the dangling-reference hazard is handled. The child index is written through `nodes_[v]` before `push_back`, and the old reference is not used after the push.
- **Update after a hit:** there is no incremental update. A fresh `FastScan` (trie, Q nodes, u lists) is built at every restart from the rewritten `exps`. That is trivially correct (it costs O(total length) per restart). The keys are carried as before, and they are conjugation-invariant.
- **Sizes:** int32 node ids are ample for N ≈ 2,000 certificates.

## (3) Tests: PARTIAL (non-blocking)

| Risky case | Covered? |
|---|---|
| \|ρ\| = 1 | Yes: a⁵ and b⁵ are in `smallMap` and in the padded table. |
| \|ρ\| = 2 | **No unit test.** No relator with a root of length 2 ((ab)⁵, (aB)⁵) is in either table. It is reached only by the env-gated tests on stored b25 certificates (`ONION_CERTS`), which ctest skips by default. |
| Tables that are not cyclically reduced | Weak. The "padded" entries (aaAaaaa, abBbAB, bbbbBbb) freely reduce to *cyclically reduced* relators (a⁵, abAB, b⁵), so p ≠ ∅ comes only from conjugators. That is mathematically the same path (the `Form.p` split), and random conjugators cover it, but no table entry of the form q r q⁻¹ (like the 1,080 b25_full entries) is in a unit test. |
| Suffix-form hits | Not shown. The traces carry `prefix_form`, but no test counts or asserts any suffix hit. |
| Periodic closed form (m > m_explicit) vs the explicit m | Not shown. There are no path counters. The random conjugators have length 0–3, so the long walks depend on prefix products along a⁵/b⁵ chains. |
| Fallbacks (unsupported / verify mismatch) | Not shown. A verify mismatch silently falls back, so `checked` mode cannot see a lookup that proposes a wrong s. The result is still correct, but such a lookup bug would go unnoticed. |

The tests do compare fast with direct and with the pre-T-024 reference: the same hit sequence and the same factors, on 1,500 + 800 random certificates. They also run `checked` mode on both tables.

## (4) `checked` mode: CONFIRMED

At every restart it runs `FastScan` and `directScan` on the same state, and compares the whole first hit (i, j, s, form), including "no hit". It throws on any difference. The fast hit is then applied, and it equals the direct one.
- A missed or later hit from the lookup is caught here.
- A wrong hit is caught one step earlier, by `verify_`. Its fallback means `checked` passes, so see the recommendation below.

## Addendum 2026-10-18: re-check of the fixes (read-only, tcgraph-perf working tree)

**VERDICT: findings (3), (4) and the nit are CLOSED.** One non-blocking test-accuracy remark remains.

- **(4) checked mode.**
  - `fallback_` counts an unsupported pair or a hit rejected by `verify_`, and in checked mode (`strict_`) it throws `std::logic_error`. Fast mode still falls back to the loops.
  - The remaining fallbacks are legitimate and are counted: `direct_pairs` (an expansion with an empty core) and `direct_scans` (a letter outside a, b).
  - The first-hit comparison with `directScan` at every restart is unchanged. Closed.
- **(3) tests.**
  - The new `ShortRootsAndNonCyclicallyReducedEntries` table contains (ab)⁵, so |ρ| = 2 is covered, and also a⁵, the commutator, and the rotations of (aab)⁵ and (ab)⁵.
  - The random-table test and the short-root test assert unsupported = 0, rejected = 0, and suffix and closed-form hits > 0. The short-root test also asserts direct scans = 0 and m = 0 hits > 0.
  - Reported counts: random — suffix 242, closed form 237; short-root — suffix 131, explicit 5, closed form 115.
  - The fast result equals the direct scan and the pre-T-024 reference. Closed.
- **Nit:** `code_()` throws on a letter outside a, b. Closed.
- **Remark (non-blocking):**
  - `Word::operator*` does not reduce, so the entries (−q)·r·q with q = B are the raw words b(aab)⁵B and b(ab)⁵B. Their raw form is not cyclically reduced, which is what `isCyclicallyReduced` asserts.
  - But their *expansions* free-reduce to b(aab)⁴aa and (ba)⁵, which are cyclically reduced rotations: p = ∅. So the comment "conjugator and root are then both non-trivial" is not what happens.
  - This is immaterial for correctness: the lookup only sees the freely reduced expansions, and p ≠ ∅ comes from the random conjugators (length 1–3) in every test.
  - The rotated entries do exercise a non-trivial rotation z (r ≠ 0) against (ab)⁵ and aab-class factors, which is useful.
  - To make the test do what its comment says, use a q that does not cancel, e.g. q = A, giving a·(aab)⁵·A, whose expansion has p = a. Explicit-m hits (5) are not asserted.
