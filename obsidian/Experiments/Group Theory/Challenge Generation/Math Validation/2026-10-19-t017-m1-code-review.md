## Verdict per item

**1. Block contiguity (Hurwitz moves). SOUND.**
- `gather` (`patch_surgery.cpp:59`): pulling a member s left past o uses o s = s (s⁻¹ o s); pulling right uses s o = (s o s⁻¹) s. The conjugator update (c y), the expansion update y⁻¹ x y, and the index bookkeeping (erase/insert, lo/hi) are all correct.
- `gatheredProduct` tracks only the members. That is enough: passing a non-member never changes a member, so it gives the same block product as `gatherBlock`. A mismatch would hit the L0 throw.
- All m! orders are tried (24 at k = 4).

**2. L0 after every rewrite. SOUND, with one required fix.**
- Every candidate is compared with `target` before measuring (`:480`). Every accepted rewrite and every closure result is compared again (`:435`, `:514`). Any break throws `logic_error`, so it hard-fails.
- Soundness rests only on two facts: every table entry is a relator of B(2,5), and the expansion is unchanged. The fillings in (d) need no separate trust.
- **Required fix:** `runSurgery` sets `target = expand(start certificate)` (`:424`), and `surgery_run` never compares it with the input `word` (only `--check-only` does). A certificate in the wrong table, or for the wrong word, would be "improved" consistently.
  - Fix: in the app, call `checkCertificate(ctx, in.cells, in.word)` before `runSurgery` whenever the record has a word, and fail the record otherwise. Better still, give `runSurgery` the word.
  - **Ruling.** (a) The 12-word runs may start now: I verified L0 of all 12 inputs independently (own Python expansion, plus the no-op test). (b) Any other input file (the seed-519 component certificates, anything from the Experimenter) must not go through `surgery_run` until either the fix lands or I have run the same expansion check on that file. I recommend the fix: two lines, and it removes the dependency on me.

**3. Tests (a)-(d). SOUND.**
- (a): the block product is empty; the block is deleted.
- (b)/(c): `RelatorClassIndex::match` returns a factor whose expansion equals P exactly (documented contract, and checked again by L0).
  - The index keeps the *first* entry of a class (`emplace`). So a u⁵ duplicating an R7 class is labelled (b) and does not falsely set "extended".
  - The app appends u⁵ and (u⁻¹)⁵, so both orientations are indexed.
- **u primitive / cyclically reduced (`validateExtendedTable`). SOUND.** `minimalPeriod` is the primitive root (shortest exact tiling). The check requires |w| = 5|root|, w freely and cyclically reduced, and the root cyclically reduced. A non-primitive u (u = x², so the entry is x¹⁰) or a non-reduced u throws. The unit test covers both.
- **(d) orientation. SOUND.**
  - The pool is keyed by the rotation/inversion class, and a hit needs exact rotation equality: first with the stored core, else with its inverse, using `inverseCells`.
  - I checked the conjugator g = v·α·u⁻¹ by hand: g⁻¹ (stored) g = product.
  - The hit is re-expanded and compared with the queried product (it throws otherwise). A hash hit alone is never used.
- **Scope (not a defect):** (c) fires only for u in the `--extra-u5` list. A block conjugate to u⁵ for an unlisted u is not detected. Without `--extra-u5`, (c) is off and every result is R7-only.

**4. Re-fold and depth re-measure. SOUND.**
- After every acceptance the pass restarts. `forEachCandidateSet` folds the new certificate (`:285`), and every candidate is measured on its own fold.
- The measure is `strictDepth` S2 and `strictDepthFlip(absorbed_only)`, which is rule (d). The no-op check reproduces Lead's rule-(d) values on all 12.
- Adjacency is "shares an edge class". The ESU enumeration (enumerate subgraphs, each connected set once) matches brute force in the unit test.

**5. Strict lexicographic order (no cycling). SOUND.**
- A step is accepted only on `measureLess` (`std::tie` over (N, flip, S2), or (flip, S2, N) for depth_first). Closure results face the same test.
- The order is well-founded on ℕ³, so every run terminates.
- The `failed` memo caches only algebra misses. Those depend only on the ordered member cells and the pool, and the pool is fixed during a run. Measure rejects are not cached. A 64-bit key collision could only skip a set (incompleteness, not unsoundness).

**6. Area-neutral depth drops logged separately. SOUND (logging).**
- Each event carries `area_neutral` (N unchanged) and `closure`.
- In area_first, block rewrites always lower N, so area-neutral events can only come from the closure step. In depth_first, equal-area pool swaps are allowed.
- **Record:** the summary line has no count. Tally `area_neutral` events separately when reporting depth drops.

**7. Caps and incremental output. SOUND, with notes.**
- The CPU cap (process `clock()`) is checked before every candidate set. A capped run returns its best certificate with `cpu_capped` set. Each certificate is written as one flushed JSONL line when it finishes (append mode).
- Not covered by the cap:
  - one set's 24 orders and the measure calls;
  - the `closureFixpoint` step (bounded by 20 rounds).
  So the overrun is small on level-2 sizes. On the 1,548-letter level-3 word, give an outside wall-time limit too.
- Events inside one certificate are not streamed (`on_event` is unused by the app). A kill from outside loses that certificate's events, but not earlier lines.

**8. `conjugateCells`/`inverseCells` moved into certificates. BEHAVIOUR-PRESERVING.**
- The bodies are identical except for `rotated(X,a)` → `X << a` (a left rotation, the same for a < |X|), `prefixOf` → `subword(X,0,a)`, and an added `reserve`.
- `onion::inverseCells(ctx, …)` now delegates. All 21 ctest targets pass.

## To record in the run output (not blocking)

0. **An area-first result is not a depth bound.** Under (N, flip, S2), depth may rise while N falls. From the raw start of line 48: N 98 → 60, flip (d) 1 → 2, S2 1 → 2. Plan v2 Step 2 reads "the word's minimum" for H17. So that minimum must be taken over the start, both runs and every accepted state in the event log (`after`), never the area-first final alone.

1. **The pool is shared and grows.** `runSurgery` adds the start certificate and the result to the context pool. So in one app invocation, a later certificate can use earlier results, and results depend on input order. `--only` runs can differ from full runs.
   - Sound either way. But "upper bound under M1 at |S| ≤ k" should name the pool: the 453 references (± `--compress-reference`), plus what was added during the run.
   - Better: freeze the pool after loading the references, or log its size per record.
2. **Incompleteness of the search** (affects how tight the bound is, not soundness):
   - `bestBlockReplacement` takes the fewest-cell replacement over the orders, and only that one is measured. In depth_first, a replacement from another order that lowers depth is not tried.
   - The pool stores fillings of at most k − 1 cells and is used only for |S| ≥ 3. So equal-area swaps of k cells, or of 2 cells, are not available in depth_first.
3. **Start certificates matter.** From raw seed certificates the app reaches 31 cells on line 47 (from 144); from the pipeline-compressed 40 it reaches 22. Lead's plan (start from the pipeline-compressed certificates) is the right one. The app has no input compression, so the inputs must already be compressed: Lead's file is.

The Developer's Step 0 finding is consistent with what I ran: adjacent sets alone miss lines 13 and 48, and adjacent + all pairs reaches every target. So the control-driven deviation (adjacent + all pairs) is justified, and k = 4 with pairs is what Step 0 validated.
