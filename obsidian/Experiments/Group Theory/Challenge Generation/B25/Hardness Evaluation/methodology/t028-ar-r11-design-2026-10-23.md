**Terms.**
- **Full R:** the canonical-tie-break 2.5-reduction (§7.0e), run to its fixpoint.
- **Short cell:** a cell u^{±5} with |u| ≤ 2, i.e. u a rotation of a^{±1}, b^{±1}, (ab)^{±1}, (ab⁻¹)^{±1}.
- **N, the short-run normal form:** a fixed rewriting strategy (§1.0) that repeatedly replaces a maximal run u^k (u primitive, |u| ≤ 2, |k| ≥ 3) by u^{k−5·sign(k)}.
  - It terminates, because |k − 5·sign k| < |k|, so each rewrite shortens the word by at least |u|.
  - Each rewrite multiplies by a logged conjugate of u^{∓5}, with the core logged literally as u^{±5}. A rewrite across the wrap point is a conjugacy, not an equality. So N(z) is **conjugate** to z · ∏ cells_z in B. That is enough, since only "= 1" is carried through (argued; Validator).

## 0. What the tune set shows (as relayed; interpretation argued)

- Full R rewrites many short runs: the calibration word had 83 cells of period 1 or 2 in one R call. Those rewrites depend on context (junctions, neighbouring letters), so the true blocks end up about 3.4 edits apart per block (181 edits over 53 blocks).
- The frozen tolerance ⌊ℓ/4⌋ is 1 edit at m = 6 and 4 at m = 16. So parsing fails at small m and is marginal at large m.
- It is a **tolerance-model** failure, not a candidate-generation failure. [r11.1] Oracle-pair mode gave **2 breaks, both kbmag-dominated, and 0 recoveries** out of 18.
- The (ii-Δ) breaks were labelled "kbmag-dominated" because Δ = w · (g⁻¹ φ′(t′) g)⁻¹ contains the conjugated prefix p in p d p⁻¹ around each local difference d. So |Δ| measures the conjugators, not the size of the difference.

## 1. The tolerance model (item 1)

### 1.0 N's strategy [r11.1]

- **Base point.**
  - For w: the cyclically reduced linear word, as stored.
  - For any other word z: free reduction, then cyclic reduction by stripping matching ends, keeping the middle.
- [r11.1, pin a] **The exponent in a fractional run:** inside a maximal run of fractional length, k = ⌊(run length)/|u|⌋, read from the run start. A whole-word run (w = u^k cyclically) is first rotated to the base point.
- **Linear passes.**
  - A step rewrites the maximal run with the smallest start index. Ties go to the smaller |u|, then the larger |k|.
  - Repeat to a linear fixpoint.
- **Wrap pass.**
  - If a maximal cyclic run with |k| ≥ 3 crosses the wrap point, rotate the word to start at that run's first letter (the rotation is logged), rewrite it, and return to the linear passes.
  - Stop when neither pass applies.
- **N is not confluent.** It is a deterministic function by virtue of this strategy, not a normal form in the rewriting sense.
  - On a a a b a b a b, the leftmost rewrite gives A A b a b a b (7 letters), while rewriting (ab)³ first gives a a B A B A (6 letters) (Validator).
  - So N(w) and N(context) can also differ through the strategy itself. That does not affect soundness, and it is measured on the tune set (open question 1).
- **N against R** (Validator, argued from the score formula; not checked whether R ever applies a score-0 rewrite): for |u| ≤ 2, R fires only at integer k ≥ 3. So N and R use the same rule and differ only in order. This supports the conjecture of §1a.

### 1a. Normalise both sides, then parse (primary)

- Compute N(w). For each candidate pair, parse N(w) against **N-normalised block contexts** by a dynamic-programming parse (Viterbi over t′).
- At step i, the parse emits the a_i window of N(φ′(a_{i−1} a_i a_{i+1})). Its cost is the edit distance to the matching stretch of N(w).
- [r11.1] **The provenance rule for "the a_i window":**
  - each letter of φ′(a_{i−1} a_i a_{i+1}) carries the index of its source block;
  - free cancellation deletes letters together with their indices;
  - the letters that a run rewrite outputs inherit the index of the block holding the run's first letter;
  - the a_i window is the span from the first to the last surviving letter with index i, and it may be empty.

  This affects reproducibility only. The parse only proposes candidates.
- Rationale (conjectured): full R's short-period rewrites and N use the same local rule, so after N on both sides the remaining differences should be mostly junction and strategy effects. The edits per block should then fall well below 3.4. **This is measured on the tune set first**: the per-block edit distance between the true blocks and N(w), under the oracle alignment.

### 1b. A calibrated edit tolerance (fallback, and the cap for 1a)

- On the tune set (oracle alignment, [r11.1, pin c] the tune set's chain residuals), measure the per-block edit distance after 1a, and separately without N.
- Set κ = the largest of q95(edits per block)/m over m ∈ {8, 16}, where q95 is the 95th percentile. The tolerance is **k(ℓ) = min(⌈κ·ℓ⌉ + 1, ⌊ℓ/2⌋)** for a block of length ℓ.
  - The cap ⌊ℓ/2⌋ applies because above it a block match carries no information.
  - The +1 absorbs junction edits at small ℓ.
- κ is reported with its tune-set sample.
- [r11.1] **Unusable clause, at every m:**
  - at the tune set's m ∈ {8, 16}: the tolerance route is unusable at that m if the measured q95 exceeds m/2;
  - at the extrapolated m ∈ {6, 12, 24}: it is unusable if ⌈κ·m⌉ + 1 > ⌊m/2⌋, i.e. if the cap binds at the typical block length.
  - At an unusable m, only 1a and A_R3 run.

### 1c. Undo before parsing

- A_R3 (undoing R by cell insertion) is kept, but it **runs after N**.
- Its cells come only from (b), the block-built periods with |u| > 2. N already handles the short periods, and inverting them is ambiguous.
- The beam and the depth are unchanged.

**Soundness is unchanged** (argued; the Validator confirmed it).
- Every route proposes (x′, y′, t′, g). Acceptance is still (i) + (ii), with (ii) extended in §2.
- The N cells are logged in the same way as the A_R3 cells.

## 2. Verification and nondegeneracy for Δ (item 2)

**(ii-local), a new route for (ii).** It replaces (ii-Δ) as the default; (ii-Δ) stays as a fallback.
- Let z° be the cyclic reduction of g⁻¹ φ′(t′) g. Align N(w) and N(z°) as cyclic words:

  N(w) = c₀ α₁ c₁ α₂ … α_n c_n and N(z°) = c₀ β₁ c₁ β₂ … β_n c_n,

  where the c_j are exactly equal common segments and (α_j, β_j) are the **difference windows**. An empty α_j or β_j is allowed.
- [r11.1] **Literal check:** the implementation verifies **letter by letter** that both decompositions concatenate exactly to N(w) and N(z°), each after one fixed, logged rotation.
- **kbmag check:** kbmag (rec or slx) reduces every window loop α_j β_j⁻¹ (or a rotation of it) to IdWord, with ≤ 10 CPU-s per loop.
- [r11.1] **Caps** (inside A_R's 15 CPU-min):
  - ≤ 64 windows per candidate;
  - ≤ 120 CPU-s of (ii-local) kbmag time per candidate.

  A candidate that hits either cap is **"candidate kbmag failed"**. It is not a break, and the attack moves on to the next candidate.
- **Why it is sound (argued; Validator):**
  - each α_j = β_j holds in G_7, hence in B;
  - substituting gives N(w) = N(z°) in B;
  - N(w) is conjugate to w · ∏ cells_w, and N(z°) to z° · ∏ cells_z;
  - z° is a conjugate of φ′(t′), which is 1 by (i).
  - So w = 1 in B.

**Nondegeneracy, for attribution as a *recovery*.** This replaces |Δ| ≤ |w|/4 for this route. All of the following hold:
- **total window length** Σ (|α_j| + |β_j|) ≤ |N(w)|/4;
- **each window** has |α_j| + |β_j| ≤ 3·max(|x′|, |y′|);
- [r11.1] **block length against the word**: max(|x′|, |y′|) ≤ |w|/8, **and** |t′| ≥ 8 tokens. These are defaults: the tune set may tighten them before the freeze, and may not loosen them;
- the r10 conditions (§4 and §7.0d.2): |x′|, |y′| ≥ 2, x′ and y′ a free basis of a rank-2 H ≠ F, and |t′| ≤ |w|/2.

What this means:
- It measures **the size of the local difference, not its conjugators**. A shallow difference p d p⁻¹ costs |d|, whatever |p| is.
- A success that fails the conditions is still a break, logged as "kbmag-dominated", as before.
- [r11.1] **Why "recovery" means something** (Validator):
  - An archived survivor passed S1-each's KB check on 16 images, so kbmag alone failed on w.
  - A proof by short windows therefore adds value beyond kbmag.
  - This depends on Lead's G1 decision on what KB resilience means in S1-each.

**(ii-Δ) fallback:** for attribution, Δ's difference is measured by the same windows via the alignment, not by |Δ|. The cap of ≤ 60 CPU-s per system is unchanged.

## 3. The control set and the pass line (item 3)

**Sets.**
- **Calibration:** the Developer's tune set (20 C1 W, m ∈ {8, 16}, label "20261020|tune|m|index") with [r11.1, pin c] the tune set's chain residuals. κ, the attribution defaults, the A_R3 beam and every other r11 setting may be tuned **here only**. Then r11 is frozen (§5).
- **Control (fresh, never tuned on):** 30 C1 W, 6 per m ∈ {6, 8, 12, 16, 24}, with the seed label **"20261021|arctl|m|index"**.
  - [r11.1] **They take the first 30 non-degenerate indices**, as in the job-1 addendum.
  - [r11.1] **Clash check:** no control W may equal a tune W or a pilot W, **including the CTRL cells**. The check is recorded.
  - [r11.1, Issue 1, Lead's decision] **Residuals come from the pilot's own screen chain**, not from R alone: R (canonical) → KB (screen) → D(20M, rml 3), to a fixpoint, with the same rules as the pilot. That fills the strata.
    - **A chain cap of 8 CPU-min per word** keeps the ceiling at 30 × 8 min = 4 CPU-h.
    - A word that hits the cap keeps the residual it has at that point. Its stratum comes from the steps so far, and it is marked "chain-capped".
  - **Excluded,** with their counts reported: emptied residuals, and residuals equal to W.
- **R-depth series:** on the first 2 control W per m (arctl label), stop R after 1, 2, 4, 8 and 16 rewrites, and at full R. It is reported as a curve, and it is not in the pass line.
  - [r11.1, pin b] **Code:** the depth series and the calibration use the arctl and tune labels respectively, never pilot words. `ar_control.depth_items` defaults to pilot words today (`tune=False`). The arctl and tune label code is written **before the freeze** and is **part of the frozen repo@sha**. The control runs from the frozen code.

**Cost of the chain (Issue 1), conjectured.**
- The pilot's §7 screen estimate is about 20 CPU-s per word at |W| ≤ 2·10³ (R about 3–25 s, KB screen < 1 s, D(20M, rml 3) about 1 s).
- The Developer's measured R times on long words are higher. I put it at **≈ 0.2–1.5 CPU-h for the 30 words**, with the **ceiling at 4 CPU-h** set by the 8-min cap.
- So the chain is within Lead's "about 4 CPU-h" rule, and the pass line stays per stratum.
- **Expected thin strata** (conjectured): distillation in the pilot ends mostly in R steps. "Contains KB" and "contains D" may well have n < 10 and then be "not assessed" (below). Enlarging the control for them would be a separate decision.

**Modes, order and budget.**
- [r11.1] **Order:**
  1. **blind mode on the 30 control residuals**;
  2. **then oracle-pair mode** on the same residuals;
  3. **then the depth series.**

  A pause then never leaves the pass-line mode incomplete.
- **Blind mode** runs **at the survivor budget, 15 CPU-min**, so that the pass line speaks for the budget actually used on survivors.
- **Oracle-pair mode** runs at 3 CPU-min, as a diagnostic: it tests the tolerance model and the verification on their own.
- **Ceilings:**
  - chain 4 CPU-h;
  - blind 7.5 CPU-h;
  - oracle 1.5 CPU-h;
  - depth series 10 W × 6 depths × 3 min = 3 CPU-h;
  - **in total about 16 CPU-h.**
- **Expected** (conjectured): about 1 CPU-h for the chain plus about 3–5 CPU-h for A_R. The Validator estimates 3–5 CPU-h for A_R from the Developer's 2.5–4 CPU-min per failing blind run.
- **Pause:** the A_R control pauses at **4 CPU-h** (the chain not counted) and re-plans with Lead. It will probably fire during or after the blind phase. Raising it is Lead's call.

**Pass line.**
- **A_R r11 passes in a stratum** (R-only, contains KB, contains D) if blind mode **recovers** ≥ 50 % of that stratum's control residuals, by the **point estimate** [r11.1].
  - The Wilson 95 % interval and the pooled rate are reported beside it, but neither is used for the rule.
  - Only a **recovery** counts toward the pass line, i.e. a break that meets the §2 nondegeneracy rule. kbmag-dominated breaks are reported, but they do not count.
- [r11.1, pin c] **Reported next to the pass line:** the chain-capped count and the step mix (R / KB / D steps per residual). If more than about 1/5 of the control words are chain-capped, the report says that the control reflects shorter chains than the pilot's.
- [r11.1] **A stratum with n < 10 is "not assessed".** Its survivors' r11 failures stay "attack-limited".
- [r11.1] **Not comparable with r10:** r11 counts only recoveries, while r10 counted breaks. The report says so wherever both appear.
- **Diagnostic line:** if oracle-pair mode recovers < 80 % of the R-only stratum, the tolerance or verification model is inadequate whatever the blind rate. Report it to Lead and the Math Expert before using r11 on survivors.
- **If r11 fails** the pass line in a stratum, or the stratum is not assessed, its failures on survivors in that stratum stay labelled **"attack-limited"**, as in r10. The label is interpretive only: the tiers are unchanged, and an unbroken word stays unbroken.
- **Expectation (conjectured):** R-only passes. "Contains D" does not (coset-table geodesics); this is unchanged from r9.

**C3 words with planted structure as the KB-rich part? No** (argued).
- The planted structure of a C3 arctl word is known (three pairs, t_j, signs, conjugators). But A_R's output and its success condition are **single-pair**: w = g⁻¹ φ′(t′) g with one (x′, y′).
- A K = 3 word is a product of three conjugated images in three different rank-2 subgroups. One pair covers about a third of it at most, and the rest becomes difference windows far above the |N(w)|/4 attribution bound.
- So on C3 words the control would measure this **structural limit**, not the attack's reach. Their "no break" is attack-limited in every stratum.
- Making A_R K-pair (w = ∏_j g_j⁻¹ φ_j(t_j) g_j with segmentation) is new mathematics. It would be an r12 with its own review, and it is not proposed here.
