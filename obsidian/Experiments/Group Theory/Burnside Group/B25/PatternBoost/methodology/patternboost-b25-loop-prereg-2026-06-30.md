## §2 Success Metric — Cooperation Gain (doctrine P5)

Let:
- `L_loop(w)` = length of the shortest word found by the full loop (N rounds) starting from seed `w`
- `L_baseline(w)` = length of the shortest word found by braid_reduce alone, running iteratively on the same seed, using the **same number of scorer calls** as the loop

**Cooperation gain:** `L_baseline(w) − L_loop(w) > 0` for at least one seed `w`.

**Primary metric threshold:** Cooperation gain > 0 on ≥1 seed, backed by GAP word-equality verification. A tie (`L_loop = L_baseline`) is **not** a success.

**Null-result threshold:** After N_max rounds with no seed achieving cooperation gain > 0, record as null result. Do not interpret as evidence about free B(2,5).

### Reducer-alone baseline (how to compute — PRIMARY)

Run braid_reduce iteratively on seed `w` with **identical config to the loop scorer** (--no-beam; --rules-file when that extension lands; see §8):
```
w₀ = seed_word
wₖ₊₁ = braid_reduce(wₖ, --no-beam [--rules-file seed_rules.kbprog])
```
until `len(wₖ₊₁) == len(wₖ)` (converged) or same call budget as loop exhausted. `L_baseline = len(final wₖ)`.

**Why identical config:** if the baseline uses beam and the loop uses --no-beam, a win for the loop could reflect beam vs no-beam, not transformer contribution. Config must match to isolate the transformer's effect.

**Optional Baseline B (harder bar):** Run with full beam (`--beam-width 4096 --beam-secs 30 --rules-file`). If the loop also beats this, the cooperation-gain claim is stronger. Record Baseline B separately; it is not the primary metric.

**AMENDMENT 2026-06-30 (confirmed measurement, B25 Experimenter):** Both PRIMARY (--no-beam) and Baseline B (beam 4096/30s) give **260 → 260 (Δ=0)** on `comm_13_10_lifted.txt`. braid_reduce is completely blind on this word in all modes. The 31 seed rules also do not fire (all LHS ≥41 chars; compressed segments are shorter). Cooperation-gain target = **< 260 chars** (any improvement). The '258-char' figure from an earlier pre-reg draft was kbprog-derived, not braid_reduce-derived — that is Baseline C (separate methodology). Training signal in round 1 will be initially all-zero until the transformer proposes structurally different candidates.

Record convergence point for both. Primary baseline = `--no-beam`. Confirmed value = **260**.

## §4 Scoring — Reducer-Shrink (B25 Experimenter section)

### Score formula

```
reduction_ratio = (len_in − len_out) / len_in    ∈ [0, 1]
```

Source: `BurnsideDataPoint.calc_score()` in `feat/burnside-datapoint:experiments/burnside/b25_patternboost/datapoint.py` commit `1c6f1ff`.

### Scoring pipeline (expand-then-score)

```
candidate_word (m/M alphabet)
  → compress_words.expand() → base {a,b,A,B} word
  → braid_reduce --no-beam --rules-file seed_rules.kbprog
  → reduction_ratio = (len_in − len_out) / len_in
```

**Why expand first:** The 31 GAP-verified seed rules are in `{a,b,A,B}` and will not match m/M subwords. Expanding before scoring allows all 31 rules to fire.

**Confirmed:** `braid_reduce` supports `--rules-file` (confirmed from `stage2b_reducer.py` which uses this flag; command signature unchanged). The 31 rules go into the SCORE step, not a separate kbprog pass.

## §6 Loop Architecture (Developer section)

### One round

```
Round k:
  1. PROPOSE
     Round 1: seed corpus (comm_13_10 compressed, 260 chars in m/M)
     Round k>1: transformer generates N candidate words (token sequence → m/M string)

  2. EXPAND
     For each candidate (in m/M): compress_words.expand(candidate) → {a,b,A,B}
     Must precede LOCAL SEARCH: local_search() calls _free_reduce() whose INVERSE dict
     does not contain m or M — passing m/M chars causes a KeyError.

  3. LOCAL SEARCH (repair, Python, <1ms/word)
     BurnsideDataPoint.local_search() on the EXPANDED {a,b,A,B} word:
       - free reduction (cancel x X⁻¹)
       - power reduction (g^5 → ε, g^4 → g⁻¹, etc.)
       - braid reduction on alternating runs ≥6
     NEVER increases word length.
     CAVEAT: Python reducer misses products-of-conjugates class
             (e.g. (aba)^5 stays length 15). Local search is proposal repair only —
             NOT an identity test.

  4. SCORE
     BurnsideDataPoint.calc_score() on the (expanded, locally-searched) {a,b,A,B} word:
       braid_reduce --no-beam [--rules-file seed_rules.kbprog — see §8 for delivery status]
       reduction_ratio = (len_in − len_out) / len_in
     Parallelism: do_score() num_workers=2 (4-proc global cap).
     Timeout: 30s/word.

  5. FILTER + TRACK BEST
     Keep score ≥ 0 (valid) candidates.
     if len(expanded_reduced) < len(global_best_expanded):
       global_best = compress_words.compress(reduced_word)   ← re-compress if improved

  6. TRAIN
     Update transformer on (tokenized ORIGINAL m/M proposal, reduction_ratio) pairs.
     Train on the PROPOSAL (before expand/repair), not on the repaired form.
     Training signal = reduction_ratio (Maria's fixed decision).

  7. REPEAT until convergence or N_max rounds
```

### Termination

- **Convergence:** global_best unchanged for K consecutive rounds (default K=3).
- **Budget:** N_max rounds reached (TBD at impl time, default N_max=20).
- **GAP check trigger:** any candidate that beats global_best must be GAP-verified (word-equality in B₀(2,5)) before recording as a reduction claim. Abelianization NOT sufficient.

### Process budget enforcement

- Before any heavy subprocess: `pgrep -c braid_reduce` check; block if ≥2 running.
- do_score(): `num_workers=2` maximum.
- Transformer training: 1 process.
- Total: ≤4 procs concurrent. **HARD CONSTRAINT — 4 PROCESSES MAX IN TOTAL FOR ALL AGENTS.**

### Artifact persistence

Per round, persist to `runs/b25/patternboost_loop_v1/<timestamp>/`:
- `global_best_round_k.txt` — compressed m/M string
- `global_best_expanded_round_k.txt` — expanded {a,b,A,B} string
- `scores_round_k.csv` — (candidate, score) pairs
- `transformer_round_k.ckpt` — model checkpoint
- `gap_verification/` — command + GAP output for any reduction claim

## MANDATORY RESULT SANITY GATE (added 2026-07-21, Lead — Maria escalation after the 20260630 reward-hack)

**No run may be reported as a positive result (`COOPERATION_GAIN`, `beats_beam=True`, a recorded
reduction) until it passes ALL of the following.** Enforced in code by
`sanity_gate.validate_positive_result(...)`, wired into `loop.py`, `run_v1a_ab.py`, `v1b_pilot.py`.
A run failing any check is labeled `hypothesis_result='INVALID_GATED'` with reasons — never a discovery.

**★ SOUNDNESS SUBTLETY (Validator, why GAP-equality alone is insufficient):** the benchmark words are
=e in B₀ BY CONSTRUCTION (HWW relators). So `candidate C =_{B0} original W` reduces to `C =_{B0} e`,
which the EMPTY WORD and every trivial-in-B₀ word satisfy. **GAP-equality alone therefore CANNOT reject
the empty collapse on these targets** (exactly how the hack slipped). The accept gate MUST be the
CONJUNCTION of THREE checks — GAP-equality is necessary but not sufficient:

1. **Element-preservation (GAP-in-B₀):** best `=_{B0}` original W via the verified pc-object oracle
   (`runs/b25/gap_oracle`, |B₀|=5³⁴; finite-pc element eval, NOT abelianization/KB). General gate;
   WEAK on =e targets, so never sufficient alone. Element-CHANGED shorter candidate → REJECTED.
2. **Anti-degeneracy floor:** best non-empty AND `len(best) ≥ MIN_CERT_FLOOR` (DECLARED, pre-registered
   constant, justified — NOT tuned to produce a result). Empty / below-floor → invalid (−1.0).
   LOAD-BEARING precisely because check 1 is weak on =e targets. Objective = short NONTRIVIAL
   certificates / valid reduction PATHS (toward the OPEN free-B(2,5) question), NOT "is W=e in B₀"
   (trivially known); even a valid-path reduction to empty is a degenerate, rejected result.
3. **Valid witnessed path:** the accepted best must be reached by an ACTUAL witnessed sequence of
   B₀-valid reduction moves from W (reducer steps / guarded-core commits) — NOT merely a word that
   coincidentally =e. A no-path candidate that happens to be =e is REJECTED.
4. **Baseline reconciliation + degenerate hold:** `cooperation_gain` reconciled vs the braid_reduce
   baseline (gain > the rule set's physical shortening capacity → AUTO-FLAG); any `best_len==0` OR
   `max_score==1.0` → HELD FOR MANUAL REVIEW, never auto-labeled a discovery.

**Provenance of the gate:** the 20260630_181754 run reported `COOPERATION_GAIN` for an EMPTY best word
(certificate collapsed to nothing) with no valid reduction path (baseline blind, 260→260). Root cause:
reward-ratio credited shortness with no empty/GAP/floor gate. See
`[[2026-07-21-scoring-reward-hack-incident-and-honest-result]]`. Regression tests pin the three
rejection cases (empty / GAP-trivial / element-changed). Validator re-verifies the gate's soundness.
